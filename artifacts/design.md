## Chosen mechanism

Keep class_layout's immutable sealed record as the sole physical-owner authority. Replace for_each_field/for_each_instance_field and the private duplicate traversal with two scoped typed iterators, ClassFields and InstanceFields. A higher-ranked callback consumes a view whose row slice cannot escape. ExactSizeIterator supplies count from the same projection used to traverse. No cached second layout, field count, field list, or mutable registry is introduced.

For a nonempty record, hold the existing token-bound PinnedTuple owner throughout the callback. It owns the record, which owns the row tuple and names. Use its internal dec_ref_bits path rather than PtrDropGuard's public runtime RC entry. The pin must survive callbacks that change __class__ and retire the old class. Names and pointers cannot be used after the scoped callback without an independent owner.

For an empty record, pass a static empty iterator and skip the pin, missing-singleton preparation and physical base/extent projection. Reading an already sealed exact tuple, checking its length and taking a pin invoke no Python callback. The class/instance is owned by the caller through projection. No reference to the unpinned rows escapes the empty path.

InstanceFields computes field_base and physical extent once per nonempty traversal. Each next checks alignment, checked end arithmetic and the same extent bound before yielding a typed row and raw slot pointer. Native subtype tails remain described by native_instance; intrinsic payload and dictionary tail never become declared/inferred owners. Compatible __class__ changes cannot move the payload. The caller must keep the instance alive throughout traversal and may not resize or destroy its allocation.

Initialization prepares the canonical missing singleton only when a physical row exists, then fills every row. Dictionary materialization/replacement/deletion retain the existing staged ownership protocol: collect owners, publish the new state, then release displaced values so reentrant finalizers see the new state. Declared and hidden inherited slots stay separate from inferred names and dictionary entries. Reset still reserves/stages all slots before destructive writes; its capacity comes from the same iterator length. No callback may invalidate physical payload storage.

## Invariants and consumers

- Keep class construction dispatch unchanged: inherited/overridden __new__, foreign __new__ result, __init__ exactly once, invalid __init__ return, and raised exception identity.
- Preserve empty classes, slots-only, slots plus dictionary, duplicate/hidden inherited slots, native subtypes with variable tails and layout-compatible class replacement.
- Preserve one public dictionary identity across __dict__/vars, in-place mapping update, replacement and deletion. No eager dictionary for plain construction and no inline duplicate owner after materialization.
- Traverse every physical owner exactly once, including hidden slots, for GC and cycle clearing. Retain class layout until the last instance edge is retired; keep missing distinct from None and both float zeros.
- Keep pickle/dataclass round trips and failure-atomic publication/reentrant release behavior.
- Keep unsupported/task layouts excluded before touching class rows. Keep native cursors/payload excluded from fields.

## Alternatives, prior art and limits

CPython 3.12 managed inline values and demand dictionary materialization inform reuse of Molt's existing storage transition (https://github.com/python/cpython/blob/v3.12.0/Objects/dictobject.c and Objects/object.c). No code is copied. V8 maps/hidden classes illustrate doing shape work once (https://v8.dev/docs/hidden-classes); Molt already has sealed layouts, so adding a V8-like shape cache would be redundant.

Rejected alternatives: a second count/layout projection (duplicates work), eager dict allocation (regresses plain construction and ownership), name-matched constructor lowering (unsound for Python overrides), and class lookup-cache changes (an experiment did not eliminate instruction variability and was completely reverted). A simpler generic visitor was measured first; the scoped iterator also removes repeated count traversal and empty-layout preparation without introducing a second authority.

### Responses and resulting obligations

1. Architect 1 / implementer 2: next() asserts the same conditions as the prior traversal. It never returns None for a malformed row. Such a row is an internal sealed-record invariant violation, not recoverable user input. class_layout::prepare builds checked offsets, validates the staged projection with validate_class_field_offsets before publishing the sealed record, and checks extent arithmetic before allocation. The existing malformed_field_offsets_fail_before_private_publication witness independently rejects misalignment, negative/out-of-range offsets and duplicate physical offsets; allocation overflow/underflow is covered by class_instance_extent_underflow_replaces_prior_error_with_memory_error and class_instance_allocation_capacity_failures_record_memory_error. We preserve those canonical boundaries and fail-closed assertions; no second validator or fallible iterator is added. ExactSizeIterator returns exactly the remaining rows for admitted records. No user-recoverable error can occur midway through valid sealed-row traversal.

2. Architect 2 / implementer 1: both entry functions are unsafe. HRTB constrains borrowed rows only; copied ClassField names and raw slot addresses may escape. Callers must independently own escaped names/values, keep the instance allocation live and unmoved, obey GIL custody, never create Rust references held across reentrant mutation, and never use slots after the allocation dies. Add explicit Safety documentation at both canonical APIs. Existing raw-pointer consumers remain unsafe; a new slot wrapper would duplicate established raw field ABI without proving allocation custody. Do not claim Rust lifetimes prove raw-pointer ownership.

3. Architect 3 / implementer 3-4: traversal snapshots the sealed layout at entry, while each yielded raw slot reads its current value when the consumer accesses it. Compatibility requires identical physical offsets/kinds/names, extent and native representation, as enforced by the existing class attachment policy and fields_match. A class change can retire old metadata but cannot move the instance. Add a focused runtime test: switch class after the first row, retire the old class references, continue the old pinned rows, assert both slot addresses/values and the record retain count. Also check the pin balances on early return and Rust unwinding. The test uses a separate observer owner to inspect refcounts safely, so it detects a missing pin directly rather than relying on a use-after-free crash.

4. Architect 4 / implementer 3: PtrDropGuard::new drops by molt_dec_ref, whose only body under with_gil_entry_nopanic calls dec_ref_ptr. PinnedTuple drops through dec_ref_bits -> dec_ref_ptr with the already held PyToken. Both reach identical finalization/bridge/refcount validation. The non-Send PyToken proves the same thread holds the GIL; the callback is synchronous. No preserve_error transaction was used by the old PtrDropGuard::new, so none is removed. RAII balances the owner on normal return, early exit and unwinding; add the explicit pin-balance witness above. The change removes redundant runtime entry, not destructor behavior. Panics remain internal failures, not supported Python exceptions.

5. Architect 5 / implementer 4: iteration alone does not promise a coherent edge snapshot under arbitrary mutation. Initialization writes an unpublished allocation without Python callbacks. Layout preparation only copies rows/names while its parent classes remain owned. fields_match compares metadata without callbacks. GPU selection only reads slots, then performs its existing operation after the traversal. inferred_inline_owners collects pointers/value bits without callbacks, then stages/publishes/relinquishes owners under its existing protocol. reset counts/reserves/collects before writes and deferred releases. GC visitation callbacks record/count managed edges and do not run Python or mutate the receiver. GC clearing detaches into DetachedEdgeSink, releases after complete detachment. Thus these consumers do not mutate field ownership during iteration. Reentrant releases remain outside the traversal; existing field_abis_publish_before_release_and_preserve_reentrant_replacement and replacing_and_resetting_dictionary_never_reacquires_retired_inline_owners cover their publication order. Arbitrary mutation of ownership by a GC visitor is outside its unsafe contract. Preserve that restriction in API comments, with compatible class replacement as the only explicitly supported mid-traversal metadata change.

### Architect findings


1. **High — `ExactSizeIterator` lacks a defined invalid-row contract.** In “Chosen mechanism,” each `next()` checks alignment, arithmetic overflow, and extent bounds, but the design never specifies what happens when a check fails. Returning `None` early contradicts the advertised length; failing after initialization/reset has begun can leave partial state. Require either complete validation before publication or a fallible traversal with explicit cleanup semantics. Test overflow, misalignment, and out-of-bounds rows.

2. **High — Scoped lifetimes do not establish the full memory-safety contract.** A higher-ranked callback can constrain borrowed row slices, but raw slot pointers and copied name handles can escape those lifetimes. Keeping the allocation alive also does not prevent conflicting references during reentrant mutation. Specify which operations are unsafe, prohibit references across reentrant calls, and identify where pointer validity and ownership obligations are enforced. The callback signature alone cannot provide these guarantees.

3. **High — Reentrant `__class__` replacement needs traversal semantics.** Pinning the old record preserves metadata, but does not establish whether continuing under that record remains semantically correct. Define whether traversal uses an entry snapshot, and what compatibility guarantees about offsets, owner classification, and slot meaning make that snapshot valid. Explicitly test a callback changing `__class__`, releasing the last old-class owner, and then continuing traversal.

4. **High — The internal decrement substitution needs an equivalence argument.** “Use its internal `dec_ref_bits` path” assumes the public RC entry contributes no required behavior for these owners. The design should state the relevant token/thread requirements, finalization behavior, and cleanup behavior during failure or unwinding. A smaller first change would preserve the established pin/drop mechanism while replacing traversal; qualify the RC substitution separately.

5. **Medium — “Every physical owner exactly once” is ambiguous under mutation.** A pinned layout freezes the row description, not the values stored in its slots. If callbacks replace values or materialize/delete a dictionary, visiting each address once does not necessarily visit each owned edge once. Specify which consumers permit mutation, when values are captured or retained, and how ownership transfers interact with GC visitation and edge clearing. Name focused tests that trigger these transitions during traversal.

6. **Medium — The empty fast path needs a stated validation boundary.** Skipping missing-singleton preparation and payload projection is reasonable, but an empty record must already be established as a valid supported layout before that shortcut. Specify the checks shared by empty and nonempty paths and where they occur. Add explicit witnesses for empty native subtypes with tails, empty layouts with dictionaries, and excluded task layouts.

7. **Medium — Performance qualification has no decision rule.** The plan acknowledges substantial variability and correctly withholds qualification, but does not define what result would support retaining this added abstraction and RC change. Set a practical improvement/regression criterion and a bounded response to inconclusive measurements. The reported medians alone do not establish whether the optimization justifies its complexity.

These are design-contract gaps; the document alone does not establish whether the implementation violates them.

### Implementer findings

1. **The lifetime guarantee does not cover raw slot pointers.** “Chosen mechanism” says the scoped callback prevents rows from escaping, but a higher-ranked lifetime does not prevent copying out a raw pointer. Specify which operations are safe, which require `unsafe`, and who guarantees allocation lifetime and exclusive access. A lifetime-bound slot wrapper could make this contract easier to enforce.

2. **Checked iteration has no defined failure behavior.** `InstanceFields::next` checks alignment, arithmetic and extent, but the design never says what happens when a check fails. Returning `None` early could violate `ExactSizeIterator` and silently omit owners during GC; failing after initialization/reset writes could leave partial state. Define whether invalid layouts are rejected before mutation or represent an invariant violation, and ensure the reported length matches the yielded physical owners.

3. **The internal RC substitution needs an explicit equivalence contract.** Replacing public RC entry with `dec_ref_bits` assumes the omitted entry work is unnecessary for this owner. Document the required token/thread state, ownership balance, exception preservation and finalizer behavior. Test normal completion, early return and unwinding, including a callback that changes `__class__` and releases the old class’s last external reference.

4. **The reentrancy boundary is underspecified.** “No callback may invalidate physical payload storage” is insufficient: a callback can preserve allocation addresses while replacing the dictionary, changing compatible classes or clearing fields. State whether traversal observes the entry layout or current layout, whether slots are read before or after callbacks, and which mutations are permitted. For each consumer, identify where Python callbacks can occur. Where possible, finish traversal and staging before invoking reentrant releases; that is simpler to reason about.

5. **The proof plan does not explicitly exercise several new mechanism boundaries.** Add or identify exact witnesses for zero-field native subtypes with nonempty intrinsic tails, unsupported/task layouts taking the empty shortcut, checked extent/arithmetic failures, early iterator termination, and allocation failure during staging. Also tie missing/`None`/both float zeros and exactly-once hidden-slot visitation to named assertions. “Selected existing tests” does not establish these cases.

6. **Performance qualification lacks a decision rule.** The diagnostic medians improve by approximately 1.8%, 2.8% and 3.2%, while the reported new/update variability is substantially larger. Five pairs alone do not define when the optimization is accepted. Specify the paired statistic, acceptable uncertainty/regressions and inconclusive outcome before collecting final results. Keep runtime correctness, the HF-679-dependent differential gate and performance acceptance separately identifiable.
