# Python version authority

Status: partly implemented, 2026-11-07 (one Goldfish design round applied). Owner: integrator.

## Facts and their one authority

| Fact | Authority | Projections and consumers |
| --- | --- | --- |
| Pinned source of each CPython minor (tag, commit) | `config/cpython_regrtest_sources.toml` rows (a lock) | `config/cpython_stdlib_snapshot.json` receipts |
| Release (major, minor, micro, level, serial) of each pin | the receipted `Include/patchlevel.h` at the pin's commit | `src/molt/_python_release_generated.py` `CPYTHON_RELEASES` (generated by `tools/gen_stdlib_module_union.py`) |
| Supported target minors and the default minor | `src/molt/target_python_policy.py` | `release_matrix.SUPPORTED_CPYTHON_VERSIONS` and `stdlib_module_union.BASELINE_PYTHON_VERSIONS` (generated) |
| Development interpreter | the default target minor's pinned final release | `.python-version` (generated; uv, CI bootstrap and checkout provisioning read its exact bytes) |
| Reference CPython patch per target minor | `CPYTHON_RELEASES` | `verified_subset` policy `reference_cpython` (derived, no longer in the TOML) |
| Interpreter contract of gates | `.python-version` | `tools/proof_plan.toml` `python` policy (`version_file`; the loader derives `version_pattern`, `setup_value` and evidence) |

Invariant: the development interpreter is the default target's pinned patch. A change of the
default target minor therefore moves every development image; that is deliberate and visible
as a `.python-version` diff.

## Done (2026-11-07)

- `proof_plan.toml`'s `python` policy derives from `.python-version`; `pin_freshness` reads the
  Python pins from that file (683ec87f64).
- `derive_python_release` refuses a pin whose tag names another release than its
  `patchlevel.h`; no projection can carry two patches for one row.
- The release generator writes `.python-version` (registered under the manifest's `outputs`).
- `verified_subset.toml` drops `reference_cpython` (schema v3); the loader derives it from
  `CPYTHON_RELEASES`. The release consumer's `python_policy_sha256` binds the policy file and
  the derived coordinates, so a patch move invalidates consumer receipts.
- The comparisons of a configured reference against the tag are deleted
  (`compatibility_error_protocol`, `gen_stdlib_module_union --compare-sources`, report schema v2).
- Gate reruns go through the landing executor record (`tools/trunk_landing.py --record`), which
  prepares each gate's interpreter; no caller names one (cca4a60ee9).

## Remaining

1. `tools/regrtest_adapter.py` `SUPPORTED_MAJOR_MINORS` imports the target policy.
   `tools/compatibility_error_protocol.py` (source rows plus per-minor `PATHLIB_REFERENCES`) and
   `tools/gen_compat_platform_availability.py` (vendored docs columns) are data-keyed tables, a
   different fact: they keep their tables and assert coverage of every admitted minor.
2. `tools/cpython_regrtest.py` takes its default minor from the target policy, not row order.
3. `pyproject.toml` spells the minimum minor three times (`requires-python`, ruff `py312`,
   `[tool.molt.dx] python`); derive or check them against the default minor.
4. A Python pin move is one transaction: new row (tag and commit), `--refresh-sources`, the
   generators, and patch-bound evidence that must be re-measured
   (`config/python_compatibility_error_sources.json`, and `CPYTHON_VERSION` in
   `tools/perf_instructions.py`, the output reference of the instruction signal). It must also
   check that uv ships a managed build of the new patch before `.python-version` moves.

## Prior art

- `rust-toolchain.toml`: one declaration that rustup, Cargo and CI read.
- rules_python `python.toolchain(python_version=...)`: versions declared once.
- CPython `Include/patchlevel.h`: the version exists once; other spellings are generated.
- uv: `.python-version` is the selector uv and CI read, so it stays, as a projection.
