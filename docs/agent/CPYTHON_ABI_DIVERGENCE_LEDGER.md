# CPython-ABI Divergence Ledger

> **Scope.** Ranked, adversarially-verified catalogue of every place the Molt
> CPython extension-ABI (`runtime/molt-cpython-abi/`, the `molt-wasm-cpython-abi-v1`
> tier that a compiled C extension such as **numpy** links against) diverges from
> CPython 3.12 semantics. Refuted findings are excluded. Each row was checked against
> the molt Rust source **and** the CPython 3.12 primary source; ~16 highest-impact rows
> carry a full CONFIRMED verdict (marked †).
>
> **Anchor.** Line numbers are as of `origin/main` **`92f00f4817b2`** (2026-07-10).
> They are anchors, not identities — re-anchor by grepping the function name when a
> line drifts (see §4). File paths are relative to `runtime/molt-cpython-abi/src/api/`.
>
> **Legend.** Severity `[H]`/`[M]`/`[L]` is the verdict-corrected value; `(np)` = on
> numpy's imported C-API surface (`C:/Molt/tmp/numpy_imported_pyapi.txt`); `†` =
> full CONFIRMED adversarial verdict on file. Classes: **MISSING_DISPATCH** (never
> consults the type slot), **DIVERGENT** (wrong result/contract), **SILENT_SENTINEL**
> (returns -1/NULL with no exception set), **STUB** (unimplemented), **THEATER**
> (fabricates a plausible-looking answer).

materialize-on-first-read design: naively exposing `PyUnicode_DATA` as a direct
writable pointer into the final UTF-8 buffer would let a caller write a raw Latin-1/
UCS2/UCS4 byte >0x7F that is invalid UTF-8 on its own, corrupting every other string
op that assumes the runtime's str invariant. A shallow fix here risks shipping a new,
worse corruption bug than the current honestly-labeled stub; flagged for follow-up
rather than shipped.

## 3. Batch-fix plan (4 coherent lanes, one agent each)

Findings are grouped by **mechanism** (not by file) so each lane is a single coherent
cut a solo agent can own end-to-end. Every lane lands with CPython-3.12-captured teeth
(unit tests whose expected values come from the pinned interpreter, per M02/M06) **and** a
