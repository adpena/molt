# V1 Handoff Findings Ledger

Open defects, gaps and blockers found while landing the all-WIP consolidation
(PR 116) for the 2026-10-05 move to a new development machine. Each row is a
verified observation with evidence, not a plan. Work the open rows top-down,
claim a row through `docs/agent/CLAIMS.md` like any other lane, record the fix
commit in the row, and delete the row once the fix is on `main` with its stated
verification.

Evidence paths under `C:\Molt\...` exist only on the Windows host that
produced them; the public CI run IDs are enough to reproduce each finding.

## Open: CI, harness and release engineering

| ID | Finding | Evidence | Next step |
|----|---------|----------|-----------|
| HF-08 | The proof-queue real-execution suite cannot finish in its 600 s CI budget: each supervised execution takes 20-40 s on Linux CI, and only ~16% of `tests/tools/test_proof_queue.py` ran before the timeout (Linux and Windows). The supervisor build store is already shared; repeated per-test input capture (Rust toolchain/linker probes, Python identity, CAS publication) is the profiling candidate. A profiling lane was blocked locally by sandbox permissions. | Per-test durations from CI 37404291513 Linux portability timestamps. | Profile one real-execution test (M10), make deterministic captures content-addressed and session-reused with the same revalidation, then size the row budget from measurement. |
| HF-09 | WASM: `tests/test_wasm_split_runtime.py::...::test_repeated_build_preserves_complete_generation_and_executes` runs two real builds and exceeds its 300 s row budget (one build took 268 s in CI). | CI 37404291513 WASM job. | Measure the warm second build; if it is not near-free, that is a caching defect, not a budget problem. |
| HF-10 | Build footprint and duplication. One host accumulated ~70 GB under `C:\Molt\target` in ~45 target directories (one per lane, experiment and test session), each a full rebuild of the same dependency graph; PDB debug info was ~40% of a dev test build; every build re-hashes the interpreter install for build-Python admission (5 s on Windows, longer on Linux CI). | HF-11 | A single stale guard scratch entry (owner commit interrupted after the pending index was written) makes every guarded command on that host fail with 125 ("scratch pending index differs from terminal owner"), forever. | `C:\Molt\tmp\gs\pending\73bba235....json` on the Windows host. | Publish the pending index only after the owner commit, and let the sweep repair an index that disagrees with a verified owner instead of failing every run. |
| HF-12 | The full `molt-runtime` lib test suite deadlocks on Windows after ~71 tests (right after the `async_rt::process::child_resources` tests; no per-test timeout notice, so the whole process stalls), on main as well. | HF-13 | Proof-queue run evidence has no retention policy: `logs/proof_queue/runs` reached 68.8 GB on one host (2,720 entries; seven run directories held ~64 GB). | HF-20 | Rust CI had no build cache: "Rust Build And Unit Smoke" spent ~880 s of 986 s cold-compiling ~512 crates and 181 test binaries. Cached via `actions/cache` (dcd46731c, bb30cdd0a); `test_every_action_reference_is_admitted_by_repository_policy` guards the action policy. `actions/cache` saves only when the job succeeds, so the cache stays cold while the Rust job is red. | Truth-runner manifest of CI 37357000463 job 111922104524. | Once the Rust job is green, attest the saving by comparing a cold and a warm run of an identical revision. Consider a separate save step that runs on failure. |

| HF-25 | The generated proof plan hashes 314 authority inputs from the working tree, while the pre-commit freshness hook checks the stashed index.
